# evals — fact-retention benchmark for hermes-vcc

Answers the question the replay gate can't: **not "does compaction shrink and
stay deterministic" but "what do you still know after compaction"** — and how
that compares to the built-in LLM pipeline. Grist task 72; the numbers here
are the gate for default-on activation beyond pxl.

Methodology is pi-vcc's (`benchmarks/README.md` upstream), adapted to Hermes:
reference facts are established from the FULL transcript, then every candidate
producer — vcc and the baseline — is scored by the SAME checker
(`fact_bank.score`), symmetric by construction. Matching is normalized
substring (casefold + whitespace collapse), not embeddings.

## Layout

    evals/
      fact_bank.py         fact model: categories, weights, symmetric checkers
      gen_fixtures.py      regenerates the small fixtures/ (edit→regenerate)
      gen_big_fixtures.py  regenerates the two large-context fixtures
      fixtures/*.json      synthetic sessions + planted ground-truth facts
      run_eval.py          the runner (see usage below)
      gate.json            measured regression floors (--bless rewrites them)

**Synthetic-only policy (Rain, 2026-10-31):** the harness never reads live
session transcripts. Every fixture is generated by `gen_fixtures.py` /
`gen_big_fixtures.py` with planted facts; ground truth is those planted
facts, matched by the symmetric checker. Live-session economics (real sizes,
latency) are measured separately by `scripts/replay_eval.py`, which reports
sizes/latency only — never fact claims about real conversations.

## Fact model

Weights follow pi-vcc's doctrine — an error state carried forward is worth
more than an `ls`:

| category           | w | notes                                                        |
|--------------------|--:|--------------------------------------------------------------|
| failed_command     | 6 | the failure the next context window must not forget           |
| commit             | 5 | hash AND subject must both appear (when hash is known)        |
| modified_file    | 4 | prefix-trim tolerant: trailing 2 segments match the header    |
| goal / scope_change / preference / blocker | 4 | user intent and state   |
| blocker_volatile | 4 | deep/early blocker — dropping is the DOCUMENTED fresh-only policy; the low score is the measurement, not a bug |
| created_file     | 3 |                                                              |
| tracked_command  | 2 | requires the fixture's `track_commands`                       |
| identifier       | 2 | trace/ticket ids — probes the USER_TEXT_CLIP=256 wall         |
| read_file        | 1 |                                                              |

**Matching subtleties that are the whole point:** facts can survive in
different places — the structured header (capped per section) or the brief
transcript (tail-capped at `brief_max_lines`). Where a fact lands decides
whether it lives: in `big-refactor-100`, preferences within `PREF_CAP=10`
survive in the header; #11/#12 planted mid-session fall past BOTH the header
cap and the brief-tail cutoff (~round 157) and are recorded `score=False`;
#13 planted late (`score=True`) survives on the `[user]` brief tail even
though it is past `PREF_CAP`. The early pytest in long-cap-session survives
only because Tracked Commands keeps its own tail-retained bucket. Header
lists are basenames; brief-tail lines are full paths — the checker matches
both.

## Producers

- `pure` — `vcc_core.compile_summary` directly. Offline, zero host imports.
- `engine` — `VccEngine._generate_summary`: the shipped path (host strict
  redaction, SUMMARY_PREFIX, fixture `track_commands`/`brief_max_lines`
  injected into `_vcc_options`, `previous_summary` seeded for chain fixtures).
- `baseline` — host `ContextCompressor._generate_summary` against the live
  route from pxl config (`model:` block → providers registry). One real aux
  call per fixture round (chain fixtures fold iteratively). Non-deterministic
  by nature: **reported, never gated.**

Interpreter: run under `~/.hermes/hermes-agent/venv/bin/python` (the runtime
that owns the host tree). The runner self-checks for `ruamel.yaml` at startup
and re-execs with the venv site-packages pinned via `PYTHONPATH` — the
relocatable venv bootstrap on pxl occasionally comes up without its
generation prefix under load, which surfaces as a phantom
`ModuleNotFoundError: No module named 'ruamel'` in any host-chain import.

## Running

```bash
# offline regression (all 7 fixtures, pure+engine)
~/.hermes/hermes-agent/venv/bin/python evals/run_eval.py

# with the built-in LLM pipeline for comparison (spends aux tokens)
~/.hermes/hermes-agent/venv/bin/python evals/run_eval.py --baseline

# regenerate fixtures after editing a generator (facts move with placement)
~/.hermes/hermes-agent/venv/bin/python evals/gen_fixtures.py
~/.hermes/hermes-agent/venv/bin/python evals/gen_big_fixtures.py

# gate mode (floors in gate.json) / re-bless after an intentional change
~/.hermes/hermes-agent/venv/bin/python evals/run_eval.py --gate
~/.hermes/hermes-agent/venv/bin/python evals/run_eval.py --bless
```

Gate = recall/reduction floors per fixture×path (measured − 0.02), plus
determinism required on pure+engine. Re-bless only with the reason in the
commit message.

Human-genre batch 2 (structural-targeted): retention of what humans actually
need back collapses when it is mid-session — commitment-ledger 33%,
name-alias 50%, advice-session 43%, relative-dates 58% (every deictic date
dies; only restated ISO dates survive), topic-interleave 55% (two of three
thread goals ring out; the header keeps a goal stack but cannot say which
fact belongs to which thread). German currency notation is preserved
verbatim-or-not-at-all (unparsed): €2.300 mid-session rings out, late
€1.900 plus Anlieferung €180 survives byte-exact — locale reformatting is
a baseline-run hazard, not a vcc one. Floors pin these measured numbers:
a future extractor upgrade must raise them, never lower them.

Baseline numbers vary run-to-run (it is the LLM); recall misses recur,
sizes drift a few percent.

Reading: vcc is small-and-lossless on durable structure; the LLM baseline is
big and degrades exactly where it matters — blocker state (error-recovery:
0/2) and cumulative merge across repeated compactions (55.3%: iterative
rewrites drop the previous goal, commit, and preference; vcc's
section-merge keeps them). The baseline's one recall win is verbatim
identifiers past vcc's `USER_TEXT_CLIP=256` (coding-session 100% vs 96.5%)
at ~3.6× the summary size.

**Scale is the whole point of the two `big` fixtures.** At ~600 KB / ~200
rounds (`big-refactor-100`) every cap collides at once — the brief tail
ring-out, `PREF_CAP`, `FILES_CAP`, `COMMITS_CAP`, and the tracked-command
bucket — and vcc holds **100%** recall at **95.8% reduction**, byte-
deterministic, in a 10 KB summary. The baseline scored **97.2% — the LLM
itself dropped a tracked pytest invocation** — in a 39 KB summary (~3.9×
vcc). `chain-big-3rounds` folds ~475 messages in three iterative rounds:
the round-1 transcript is gone by round 3, and vcc carries round-1
goals/commits/paths forward on the section-merge alone — 100%/96.5% at
9.2 KB. The baseline also scored 100% here, but at 46 KB (~5× vcc): at
bulk the LLM hits recall by retaining near-transcript detail, while the
small fact-dense chain (`multi-compact-chain`) is where its rewrite-drift
reproduces (55.3%, loses prev goal/commit/pref every run). Negative
reductions on the tiny fixtures mean the summary legitimately exceeds a
thin input; the `big` fixtures replace that regime, so reduction is now a
meaningful number across the board.

The `big` fixture facts encode MEASURED cap behavior, not guesses — the
engine's preferences are a verb whitelist (`always use|run|keep|write|…`,
`never use|write|send|deploy|…`), so fixture prefs use only whitelisted
verbs to probe `PREF_CAP` pressure specifically; facts whose placement
proved to ring out (pref #11/#12 mid-session, `mod_101`, early commits and
the first pytest) are recorded `score=False` with the mechanism in `note`.
Header lists are basenames, brief-tail lines are full paths — the checker
normalizes both.

## What v0 is known to lose (probed, not guessed)

| gap | probe | observed |
|---|---|---|
| `focus_topic` ignored | engine run with vs without focus, byte-compare | no-op CONFIRMED — deterministic summaries identical |
| identifiers past `USER_TEXT_CLIP=256` | `ident-clipped` fact in coding-session | dropped — known gap, floor records it |
| prev Outstanding Context | multi-compact-chain `prev-blocker` | dropped — fresh-only policy by design |
| skipForProviders / skipCustomTypes | not ported; no v0 knob exists | anything non-synthetic compiles |
| touched-not-recallable-as-set | v0 ships zero engine tools (Rain 2026-10-08) | file set survives only as header/ brief lines; no query surface |
| pref whitelist is English-only | `pref-de-gap`, `pref-ar-gap` | German/ Arabic preferences never reach the header — survive only as verbatim tail until rollover |
| non-ASCII identifiers | `arabic-indic` (٤٧١١) | all ID idioms are ASCII — unrecoverable once pre-tail |
| no supersession of values | `budget-stale` (1800) vs `budget-fixed` (1600) | corrected AND superseded values both remain; engine has no contradiction-resolution surface — exhibit for the amendment design (board 197) |
| guards are header-only | `guard-synth`/`guard-xml` dropped ✓ but `secret-in-fence`, `slash-nongoal`, `q-ident` ride the tail | synthetic-prefix, XML-strip, NON_GOAL and question guards never touch the verbatim tail — fenced secrets persist there |
| one preference per user block | `pref-in-table2` | second whitelist pref in the same message is dropped |
| tracked buckets carry no outcome | `fail-tracked-e8` vs `failed-test-e8` | bucket keeps THAT pytest ran, not that it failed; error identity survives only via tail prose |
| tail lines are clipped too | `ident-past-clip` (REQ-5000) | `USER_TEXT_CLIP=256` cuts the tail line mid-sentence — fact unrecoverable from header AND tail |

Reduction on tiny fact-dense fixtures (multi-compact-chain, preference-heavy)
is negative — the summary legitimately exceeds a thin input. The `big`
fixtures are the antidote: at 200-round / 600 KB and 3× iterative-fold scale
reduction is a real ~96% number, so the gate floors on them (0.94 / 0.95) are
the ones that mean something.
